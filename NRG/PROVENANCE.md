### `code/lri_spin_boson_hpc/`: the solver package `lri_spin` and its tools

- **Authorship.** GPT-6 astra (OpenAI, used through ChatGPT) wrote both the reference solver and analyzer of the
  original study and the optimized package built on it. The package itself carries no authorship information; this
  statement is the author's.
- **Origin.**
  - The reference solver and analyzer (`reference/`) and three archived critical couplings (`inputs/x*.json`) come from
    an earlier study of the project: archive `lri_extended_comparison_study.zip`, SHA-256 `04bb8d3002b7…`, not released.
    See `inputs/REFERENCE_PROVENANCE.json` for the file hashes.
  - The author supplied the optimized package `lri_spin_boson_hpc` as the starting point of this study.
- **Port to the cluster (2026-10-02/03).**
  - Claude Code (Anthropic) read the package line by line against the reference solver. It found no numerical defect
    and changed no numerical code.
  - It then made the package safe on the *symmetry* cluster: campaign ownership, lanes, receipts and drills.
  - OpenAI Codex (requested model gpt-6-astra; the CLI did not report which model ran) reviewed the plan and inspected
    the port's code twice. Codex reviewed the cluster port only, not the numerics, the analysis or the results; see
    `REVIEWS.md`.
- **Snapshot.** The final commit is `af9b1dced46d3a3f336c397ee7b6783305ab5e91` (`GIT_SHA`). Production ran from a frozen
  copy of it.
- **Changes for this release.** The released tree is **commit `af9b1dc` minus files not needed** to test, replay or rerun
  the study. Removed:
  - `adapters/`;
  - in `benchmarks/`, everything except the four scripts the tests run (`benchmark.py`, `long_regression.py`,
    `profile_reference.py`, `rejected_alternatives.py`);
  - `PERFORMANCE.md`, `VALIDATION.md`, `validation/`;
  - `slurm/`, replaced by `NRG/slurm/`;
  - `review/`, summarized in `NRG/REVIEWS.md`;
  - `docs/ALGORITHM.md`, covered by note §3;
  - `cluster/symmetry/freeze.sh`, which needs the original git repository;
  - `inputs/example_items.json`, a duplicate of `NRG/inputs/items/example_items.json`.

  `MANIFEST.sha256.json` was regenerated for the remaining 52 files, and `make test` verifies it.
- **`src/lri_spin/` is byte-identical to `af9b1dc`.** Its SHA-256 (`3a40deb333e1…`) is the `source_sha256` of every
  manifest, record and the receipt, so it still binds every record. A checkout of `af9b1dc` therefore shows more files
  than this folder, but the same solver.
- **Dangling references.** The package's `README.md` and `docs/SYMMETRY.md` still point to removed files. They are
  hash-listed and were not edited.

### `code/campaigns/`, `code/analysis/`

Written by Claude Code (2026-10-03/07); revised 2026-10-13. Changes since production:
- **Estimator (2026-10-13).**
  - `estimator.py` is new: the settled value, plateau test and extrapolation of note §3.7.
  - `build_tables.py`, `make_figures.py` and `note_numbers.py` were rewritten to use it.
  - The error budget is now: chain depth + K/n_b spread + Λ spread, added linearly (note §4).
  - The previous estimator, the quality-range midpoint with a quadrature budget and a factor 2 on the Λ shift, was this
    study's choice of 2026-10-04. It is not part of the inherited analyzer, whose own output is the settled window.
  - `build_tables.py` still recomputes the midpoint budget, stored under `midpoint` in `results/ds13_final.json`, for
    note App. E.
- **`build_tables.py`.** It no longer writes `final_table.tex` and `endpoint_checks.tex`, which the note does not use.
  It now runs on Python < 3.12 (no backslash inside an f-string expression).
- **Added:**
  - `note_numbers.py`, which generates the note's own tables and in-text numbers;
  - `check_figures.py`, which draws the local-exponent and comparison figures;
  - `crosscheck.py` (after the second review round, 2026-10-13): the late and crossover fits used as cross-checks, not
    adopted (note §3.8).
- **Second review round (2026-10-13).** Extrapolations whose fitted ω falls below 0.01 are reported as not determined
  (the cross-check at Δσ = 0.001); bounds quoted in the note are rounded up; `run_all.sh` now only calls `make replay`
  (before, it wrote into the released folders).
- **Readability review (2026-10-15).** The note was revised after an independent reading (`REVIEWS.md` §9).
  `note_numbers.py` gained the macros and table columns the new text quotes (the plateau test with other h and window
  widths, the rule's outcome at Δσ = 0.225, the one-loop slope prediction, the dual-series differences at Δσ = 0.01,
  δ_tot/δ^{3/2}, the series sensitivity to C_7 and C_8, NRG − MC in the headline table); `make_figures.py` changed one
  title. No value of `results/` changed.
- **`results/`.** It was regenerated by `make replay` with the new estimator and is shipped as a patch over the
  production export.

### `independent_check_compare/`, `method_comparison/`

Written by Claude Code (2026-10-08). Changed for this release:
- the input paths became arguments with defaults relative to this folder, and the outputs go to `.work/` unless `--out`
  is given;
- the Monte Carlo table is read from `../MC`;
- the ε coefficient C_8 was updated from (8.067 ± 0.033)×10⁶ to the current (8.060 ± 0.017)×10⁶.
  - This moves the series references by at most 2.7e-6 (at Δσ = 0.2; 1.6e-7 at 0.225, 2e-9 at 0.24).
  - At Δσ = 0.24 optimal truncation now stops one order later (0.494194 instead of 0.494247, both ±5e-5).
  - The Borel–Padé reference 0.49422 is unchanged.
- `compare_methods.py` no longer computes the quadrature "σ pull" of NRG against the Monte Carlo study, which combined
  scales that are not standard deviations. Instead:
  - it reports the difference, the linear ratio to σ_stat + σ_sys + δ_tot, and the crossing value with σ_∞ and Δω′;
  - it carries the NRG status (points not converged in chain depth have no error).

The 2026-10-08 write-up `REPORT.md` was not released. Note §8 replaces it. Its recommendation for the near-s = 1/2 points
was overruled by the author; see `REVIEWS.md` §5.
